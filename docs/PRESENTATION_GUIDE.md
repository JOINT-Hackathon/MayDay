# 메이데이 발표·시연 가이드

기준일: 2026-11-14. 발표 시간과 대회 평가표가 제공되지 않아 **5분 발표 + 질의응답**을 가정했다. 수상 가능성을 단정하지 않고, 실제 작동하는 흐름과 아직 검증하지 않은 가설을 분리한다.

## 발표에서 기억시킬 한 문장

**“메이데이는 사회초년생이 실수한 순간의 마음과 지금 할 일을 정리하고, 그 경험을 다음 업무의 체크리스트로 다시 꺼내 쓰게 합니다.”**

서비스를 설명할 때는 `상황 입력 → 사실·걱정 구분 → 수습 행동·보고 초안 → 다음 업무 전 체크`를 끝까지 보여준다. 모델 이름은 구현 설명에서 짧게 다룬다.

## 5분 발표 구성과 말할 내용

| 시간 | 화면·슬라이드 | 발표 내용 |
| --- | --- | --- |
| 0:00–0:40 | 문제 상황 한 장 | “견적서를 잘못 보냈다는 걸 알게 됐습니다. 머릿속에는 ‘나는 왜 이럴까’가 먼저 떠오르지만, 실제로는 어떤 파일을 보냈는지 확인하고 누구에게 무엇을 말할지 정해야 합니다. 우리는 이때 마음과 행동을 함께 정리하는 도구를 만들었습니다.” |
| 0:40–1:10 | 서비스 흐름 한 장 | “한두 줄을 입력하면 사실과 걱정을 구분합니다. 이어서 지금 확인할 일과 후속 보고를 정리하고, 다음에 다시 확인할 행동 한 줄을 남깁니다.” |
| 1:10–3:10 | 실제 앱 시연 | 아래 2분 시연 순서를 따른다. 기다리는 동안 새로운 기능을 설명하지 말고 사실·해석 구분의 이유를 말한다. |
| 3:10–3:50 | 구현 구조·신뢰 기준 한 장 | “Claude는 서버에서만 호출합니다. 정해진 JSON 필드를 검사하고, 입력에 없는 사실을 만들지 않도록 지시했습니다. 그래도 사실성을 보장하지 않으므로 사용자가 고친 뒤 저장합니다. 연결 실패에도 기본 정리로 이어집니다.” |
| 3:50–4:30 | 다음 검증 한 장 | “다음 단계에서는 사회초년생이 실제로 자기 상황에 맞게 수정하는지, 다음 업무 전에 체크리스트를 다시 여는지 확인하려고 합니다. 아직 실수 감소나 업무 성과 개선을 입증한 단계는 아닙니다.” |
| 4:30–5:00 | 결론·결과 화면 | “한 번의 실수가 자기비난으로만 남지 않고, 다음 행동으로 이어지게 만들고 싶었습니다. 오늘 정리한 경험이 다음 업무를 시작하기 전 한 줄의 확인이 되는 것, 이것이 메이데이가 만들고 싶은 변화입니다.” |

슬라이드 제목 6개: **실수 직후에는 마음과 일이 엉킨다 / 한 번 적고 두 갈래로 정리 / 직접 보여드리겠습니다 / 입력을 지키는 AI 연결 / 다음에 검증할 행동 / 오늘의 경험을 내일의 확인으로**.

위 문제 서술은 제품이 겨냥하는 상황이다. 실제 인터뷰 인용이나 조사 수치처럼 표시하지 않는다. 시간이 3분이라면 문제 30초·시연 100초·구현 및 다음 검증 50초로 줄인다.

## 2분 시연 순서

발표 전 아래 문장을 메모장에 준비한다. 실제 회사·고객 정보를 쓰지 않는다.

> 견적서 v1을 보낸 뒤 최신본이 v2인 것을 확인했어요. 당황스럽고 팀장님이 저를 무능하게 볼까 걱정돼요. 상대가 파일을 열었는지는 모르고, 아직 정정 메일을 보내지 않았어요.

1. **홈 입력, 20초:** 문장을 붙여 넣는다. `직접 정리 · AI 설정`을 펼쳐 실수 유형을 선택하고 Claude 전송에 동의한 다음 `메이데이 보내기`를 누른다. 실제 키와 결과 검토를 마친 경우에만 Claude 시연으로 소개한다.
2. **마음 정리, 25초:** “보낸 버전이 다르다는 건 확인한 사실입니다. 무능하게 볼 거라는 생각은 아직 추측입니다.”라고 설명한다. 화면이 이 구분을 올바르게 했는지 직접 확인한다.
3. **지금 할 일, 25초:** 미확인 열람 여부와 정정 계획을 확인한다. `수습 도와줘`를 열어 할 일과 `팀장님께 보낼 메일`을 보여준다. “이미 했다”는 표현이 섞이지 않았는지 보고 필요하면 수정한다. 이 메일은 앱이 정리 필드로 만든 초안이며 자동 발송하지 않는다.
4. **저장, 20초:** `체크리스트에 담기`를 누른다. 다음 업무 전에 볼 행동으로 “외부 발송 전 첨부파일의 내용과 버전 확인”이 남았음을 보여준다.
5. **다음 업무, 30초:** 헤더 `내 체크리스트`에서 해당 항목을 체크하고 `다 확인했어요`를 누른다. 새로고침 후 `내 기록`에서 다시 연다. “적용 표시는 사용자가 남긴 기록이며 실제 업무 성과를 자동 판정하지 않습니다.”라고 덧붙인다.

이미 저장된 기록은 지우지 않아도 된다. 시연 자료에는 `[리허설]`을 붙여 실제 기록과 구분한다. 같은 포트·브라우저를 유지해야 같은 로컬 기록이 보인다.

## 인터넷이나 API가 느릴 때의 15초 전환

“현재 외부 AI 응답이 지연되어 기본 정리 흐름으로 이어가겠습니다. 지금 화면은 AI 결과가 아니라 업무별 기본 제안입니다.”라고 말하고 **기본 정리로 계속**을 누른다. 사실·감정 구분이 필요한 칸은 직접 수정한다. 기록이 없는 홈의 `시연 예시`, 또는 실패 라이브러리의 예시도 사용할 수 있지만 실시간 AI 출력으로 소개하지 않는다.

화면 전환으로 요청 비용이 취소되는 것은 아니다. 재시도는 한 번만 하고 반복 클릭하지 않는다. 빌드된 로컬 앱은 서버가 실행되는 동안 사용할 수 있지만, 인터넷을 끊은 상태의 전체 리허설은 별도로 해야 한다.

## 예상 질문과 답변

**Q. ChatGPT나 Claude에 직접 물어보면 되지 않나요?**

“범용 챗봇도 정리할 수 있습니다. 저희는 사용자가 프롬프트를 설계하지 않아도 사실·걱정·행동을 구분하는 고정 흐름을 제공하고, 결과를 업무별 체크리스트로 남겨 다음 업무 전에 다시 쓰도록 연결했습니다. 그 흐름의 편의성과 재사용 여부는 사용자 검증이 필요합니다.”

**Q. AI가 잘못 판단하면 어떻게 하나요?**

“JSON 형식 검증으로 화면 오류를 줄이고, 모르는 정보는 비워 두도록 지시합니다. 형식 검증이 사실성까지 보장하지는 않습니다. 결과에 초안 표시가 있고 사용자가 직접 고칠 수 있습니다. 상사의 의도나 괴롭힘 여부를 판정하는 서비스는 아닙니다.”

**Q. 왜 Sonnet을 골랐나요?**

“입력이 짧고 정해진 칸으로 한국어 문장을 정리하는 작업이라 속도와 비용의 균형을 우선했습니다. 기본은 Sonnet 5.5이며, 모델 비교 실험이 끝났다는 의미는 아닙니다. 실제 계정의 가상 샘플 결과로 선택을 검토합니다.” 비용 질문은 [Claude 가이드](CLAUDE_SETUP.md)의 가정과 계산식을 함께 제시한다.

**Q. 어디에 저장되나요? 회사 내용이 공개되나요?**

“기본 ‘내 기록’은 현재 브라우저에 저장됩니다. Claude 전송에 동의한 상황 문장은 Anthropic으로 전달됩니다. 별도의 ‘서버 기록’은 공유 서버 연결 기능이며 계정별 구분이 없는 화면이라 가상 데이터만 사용합니다.” 삭제가 이미 전송한 외부 요청까지 되돌린다고 말하지 않는다.

**Q. 정말 실수를 줄이나요?**

“현재는 정리·수정·저장·재사용 경로를 구현한 MVP입니다. 실수 감소는 아직 입증하지 않았습니다. 다음 검증에서는 도움 없이 정리 완료하는 비율과 다음 업무 전 다시 열어 사용하는 비율을 먼저 보겠습니다.”

**Q. 누가 사용하고 돈을 내나요?**

“초기 사용자는 실수나 피드백을 스스로 정리하고 싶은 사회초년생으로 가정했습니다. 반복 사용이 확인되기 전에는 유료 수요를 확정하지 않겠습니다. 개인 기록 확장이나 온보딩 프로그램 연계는 이후 검토할 후보입니다.”

**Q. 지금 구현되지 않은 것은 무엇인가요?**

“자동 메일 발송, 검증된 성과 측정, 개인 계정 기반 동기화는 이번 발표의 범위가 아닙니다. 공유 서버 연결의 계정별 보호·운영 정책은 추가 검토가 필요합니다.”

## 심사 전에 실제로 보강할 근거

- 주변 사회초년생 3–5명에게 가상 상황으로 설명 없이 사용하게 하고 막힌 단계·직접 수정한 문장을 기록한다. 이 표본으로 시장 수요를 일반화하지 않는다.
- AI 샘플의 사실 왜곡 사례와 수정 전후를 한 장으로 정리한다. 좋은 답만 선택한 결과를 전체 정확도라고 발표하지 않는다.
- 실제 대회 평가표를 받으면 문제 적합성·차별성·구현 완성도·시연 안정성에 해당하는 화면과 근거를 매핑한다. 현재 평가표와 발표 제한 시간은 미확인이다.
- 새 기능 추가보다 2분 시연을 3회 끊김 없이 수행하고, 느린 API 응답의 전환 문장을 연습한다.

## 발표 30분 전

- [ ] `.env` 입력 후 서버를 다시 시작했다. API 키가 화면 공유에 나오지 않는다.
- [ ] `npm run check` 통과.
- [ ] `npm run ai:check` 실제 호출 성공과 3건 결과의 사실성 검토.
- [ ] 같은 브라우저·포트에서 입력 → 수정 → 저장 → 적용 → 새로고침 리허설.
- [ ] 과거 예시와 실시간 Claude 결과를 구분해서 말한다.
- [ ] 연결이 느리면 기본 정리로 전환하는 동작을 연습했다.
- [ ] 서버 기록 시연 여부는 공유 서버의 실제 응답과 공개 범위를 별도 확인한 후 결정했다.
- [ ] 발표 시간·평가 기준을 대회 공지와 맞췄다.
