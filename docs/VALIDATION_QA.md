# 메이데이 검증 계획

> 기준일: 2026-11-14 · 이 문서는 **실행할 검사**를 적는다. 체크되지 않은 항목을 통과했다고 주장하지 않는다.

## 1. 배포 전 필수 검사

| 번호 | 시나리오 | 기대 결과 | 확인 상태 |
| --- | --- | --- | --- |
| Q01 | `npm run build` | 오류 없이 `dist/` 생성 | 미실행 |
| Q02 | AI 키 없이 새 브라우저 저장 공간에서 실수 유형 시작 | 대화 없이 폼에 접근, 수동 저장 가능 | MVP 변경 후 확인 |
| Q03 | `facts` 또는 `checklist`를 비운 채 저장 | 저장되지 않고 필요한 입력 안내, 기존 입력 유지 | MVP 변경 후 확인 |
| Q04 | 사실과 체크리스트만 입력해 저장 | 결과 화면에서 두 값과 업무 종류 확인 | MVP 변경 후 확인 |
| Q05 | 새로고침 후 업무 시작에서 분류 선택 | 저장 항목이 나타남. 다른 분류의 항목은 제외 | MVP 변경 후 확인 |
| Q06 | 적용 표시, 결과 기록, 기록 삭제 | 각 상태가 저장·조회되고 삭제 후 목록에서 사라짐 | MVP 변경 후 확인 |
| Q07 | 기록이 없는 상태와 분류 결과가 없는 상태 | 이유를 알려주고 시작 행동 제공 | MVP 변경 후 확인 |
| Q08 | 기존 `v1` 기록을 읽기 | 예전 기록이 깨지지 않고 조회·삭제됨 | MVP 변경 후 확인 |
| Q09 | 모바일 폭과 키보드만으로 핵심 흐름 완료 | 가로 스크롤·조작 불가 요소 없음, 오류를 텍스트로 인식 | MVP 변경 후 확인 |
| Q10 | `npm run preview`로 빌드 제공 | 홈과 `/api/status` 응답 확인 | MVP 변경 후 확인 |
| Q11 | 저장 결과나 업무 카드에서 체크리스트 팝업 열기 | 내용 표시, 닫기·Escape 동작, 닫힌 뒤 버튼으로 초점 복귀. 보기만 할 때 `usedAt` 미변경, 적용 선택 후 기록 | 로컬 빌드에서 확인 |

현재 코드에는 별도의 테스트 스크립트가 없다. 자동 테스트를 새로 만들 경우 실제 회귀 위험을 검증하는 시나리오를 우선하며, 단순 구현 복제 테스트로 숫자만 늘리지 않는다.

## 2. AI 검증

| 번호 | 시나리오 | 기대 결과 | 확인 상태 |
| --- | --- | --- | --- |
| A01 | API 키 없음 | AI 사용 불가 안내, 수동 입력·저장 가능 | 미실행 |
| A02 | 동의 없이 AI 버튼 클릭 | 외부 전송 없이 동의 안내 | 미실행 |
| A03 | 실제 키로 실수형 샘플 호출 | 구조화 응답 수신, 미확인 원인·영향을 확정하지 않음 | **실제 키 필요** |
| A04 | 실제 키로 지적형 샘플 호출 | 타인의 의도·평가 기준을 지어내지 않음 | **실제 키 필요** |
| A05 | 이미 쓴 필드가 있는 상태에서 AI 호출 | 사용자 작성값 유지, 빈 필드만 채움 | 실제 키 또는 통제된 응답 필요 |
| A06 | 요청 실패·시간 초과·한도 초과 | 원문과 작성값 유지, 오류 안내와 수동 경로 제공 | 실패 조건 재현 필요 |
| A07 | AI 제안을 수정한 뒤 저장 | 수정된 값이 기록에 남고 새로고침 후 조회됨 | 실제 키 또는 통제된 응답 필요 |

샘플 문장은 [AI MVP 명세](../AI-MVP-구현명세.md#6-승인-기준)에 둔다. 정확한 문장 일치는 검사하지 않는다. **입력에 없는 사실을 사실로 단정하는지**와 사용자가 수정할 수 있는지를 본다. 키가 없으면 A03–A04를 통과 처리하지 않는다.

## 3. 오류·보호 검사

- 잘못된 JSON, 지원하지 않는 유형, 빈 원문, 길이 초과, JSON이 아닌 본문에 대해 [API 계약](API_AI_CONTRACT.md)의 상태 코드가 나오는지 확인한다.
- 브라우저 저장 공간이 막히거나 가득 찬 경우 저장 성공으로 표시되지 않는지 확인한다.
- API 키·실제 사용자 원문이 프런트엔드 번들, 화면 오류, 일반 로그에 나타나지 않는지 확인한다.
- 기록을 삭제한 뒤 해당 브라우저의 내 기록과 업무 시작에서 사라지는지 확인한다. 외부 AI에 이미 보낸 요청까지 삭제된다고 설명하지 않는다.

## 3.1 디자인 적용 검사

- [디자인 시스템](DESIGN_SYSTEM.md) 적용 후 375px, 768px, 1024px, 1440px 폭에서 핵심 입력·저장·재조회가 가려지지 않는지 확인한다.
- 글래스 표면의 가장 밝고 어두운 배경에서 본문 대비와 키보드 초점 윤곽을 확인한다.
- 블러 미지원, 투명도 감소, 모션 감소 환경에서도 같은 정보와 버튼을 사용할 수 있는지 확인한다.
- AI 상태와 오류 메시지가 초록색 장식에 묻히지 않고 텍스트로 읽히는지 확인한다.

## 4. 사용자 관찰 계획

첫 5명은 제안한 **소규모 사용성 확인 대상**이며 모집·실시되지 않았다. 실수 또는 지적을 받은 상황을 제시하고 다음을 관찰한다.

1. 도움말 없이 경험과 행동 하나를 저장하는가? 멈춘 화면과 이유는 무엇인가?
2. 다른 업무를 시작한다는 상황에서 저장한 체크리스트를 다시 찾는가?
3. AI를 사용한 경우 어떤 문장을 수정했는가? 실제로 틀린 사실을 그대로 저장했는가?
4. AI 사용·미사용의 완료 시간과 어려움을 기록한다. 작은 표본에서 인과 효과를 단정하지 않는다.

제안 목표는 [제품 명세](../PRD-메이데이.md#3-목표와-확인-방법)의 저장·재발견 기준을 따른다. 참여자 수, 시나리오, 성공/실패, 발언의 익명 요약, 발견한 문제와 수정 여부를 날짜와 함께 기록한다. 민감한 경험 원문을 검증 문서에 복사하지 않는다.

## 5. 검증 결과 기록 양식

```text
날짜/환경:
검사 번호:
실행 명령 또는 재현 순서:
기대 결과:
실제 결과:
통과/실패/미검증:
증거 위치(스크린샷·로그 등):
남은 문제와 담당 파일:
```

시연 전에 실패한 필수 검사와 미검증 AI 호출을 명확히 남긴다. 구현한 기능과 실제 사용 결과를 같은 증거로 취급하지 않는다.
