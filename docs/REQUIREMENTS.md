# 메이데이 기능 요구사항

> 기준일: 2026-11-14 · `[현재]`는 코드에서 확인, `[이번]`은 MVP + AI v0 구현 대상, `[후속]`은 확장 후보.

## 공통 규칙

- 경험 유형은 `mistake`(실수 발견)와 `feedback`(지적·피드백) 두 가지다.
- 사용자가 직접 확인한 사실, 자신의 해석, 감정은 분리한다. 확인하지 못한 원인·영향·타인의 의도는 사실로 표시하지 않는다.
- 저장에는 `facts`와 `checklist`의 공백 제거 후 값이 필요하다. `taskType`은 현재의 네 분류 중 하나다: `문서·자료`, `회의·소통`, `일정·마감`, `기타`.
- AI 제안과 문서 초안은 사용자가 수정·검토할 재료다. 저장·전송·발송을 자동으로 진행하지 않는다.

## 예외·상태 요구사항

| 상황 | 필요한 동작 |
| --- | --- |
| 기록 없음 | 내 기록과 업무 시작에 빈 상태 및 시작 행동 표시 |
| 선택한 업무 종류에 기록 없음 | 해당 분류에 기록이 없음을 알리고 경험 정리로 이동 가능 |
| `localStorage` 읽기 실패·형식 오류 | 오류 표시, 앱 렌더 유지. 손상된 값을 임의로 덮어쓰지 않음 |
| `localStorage` 쓰기 실패 | 성공 메시지·결과 화면으로 이동하지 않음 |
| AI 키 없음·오류·응답 누락 | 수동 입력 가능, 이미 쓴 내용 유지, 실패 이유를 사용자 언어로 안내 |
| 저장 기록의 오래된 필드·잘못된 분류 | 읽기 시 기본값으로 정규화하고 화면이 깨지지 않도록 함. 현재 코드는 주요 문자열 필드와 분류를 처리함 |
| 모바일·키보드 이용 | 핵심 입력, 저장, 조회, 삭제를 키보드로 끝낼 수 있고 오류는 텍스트로도 전달 |

## 첫 버전 시나리오

1. 실수 경험을 고른다. `facts`에 “공유한 표의 합계가 원본과 달랐다”를, `checklist`에 “자료 공유 전 합계와 원본 수치를 대조하기”를 적고 업무 종류를 고른다.
2. 선택적으로 AI 초안을 받되 제안 문장을 수정한다. AI를 사용하지 않아도 같은 결과에 도달한다.
3. 두 트랙을 저장하고 분석 결과의 할 일 상세에서 체크리스트 팝업을 연다.
4. 적용할 항목을 선택해 기록한다. 새로고침 후 같은 업무 종류에서 항목과 적용 표시를 찾고, 기록을 열어 삭제한다.

요구사항의 구현 여부는 코드 변경 후 [검증 계획](VALIDATION_QA.md)에 증거를 남긴다. 현재 요구와 후속 요구를 한 번에 구현하지 않는다.
