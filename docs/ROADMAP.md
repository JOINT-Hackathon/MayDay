# 메이데이 확장 로드맵

> 기준일: 2026-11-14 · 단계는 날짜 약속이 아니라 선행 조건과 검증 순서다.

## 제품의 중심

한 번 겪은 업무 경험을 다음 업무의 점검 행동으로 바꾸고, 실제 업무 시작 시 그 행동을 다시 확인한다. AI는 이 과정을 **빠르게 작성하도록 돕는 선택 기능**이다. 사용자 성과와 반복 사용은 아직 검증되지 않았다.

## 단계별 범위

| 단계 | 만들 기능 | 통과 조건 | 이번 단계에서 하지 않을 일 |
| --- | --- | --- | --- |
| 0. 이전 데모 | 대화형 질문, 정리 폼, 로컬 기록, 체크리스트 조회, 선택적 AI·문서 초안 | 비교 기준으로만 보관. 대화형 코드는 현재 기본 화면에서 사용하지 않음 | 사용자 검증 완료로 소개하지 않음 |
| 1. 현재 MVP + AI v0 | 홈의 선택적 상황 입력, 두 트랙 폼, AI 한 번 초안 제안, 사람이 수정·저장, 체크리스트 팝업과 업무별 재조회 | 구현 상태와 실제 검증 결과는 [검증 계획](VALIDATION_QA.md)에 기록. 실제 키가 없으면 AI 성공은 미검증으로 표시 | 자유 대화, 자동 발송, 로그인 |
| 2. 재사용 강화 | 저장 항목 편집, 적용 결과 기록의 흐름 정리, 체크리스트 재사용 이력 | 관찰 참여자가 저장 항목을 다시 찾고 사용하려는지 확인한 뒤 범위 확정 | 근거 없는 개인화 추천 |
| 3. 계정·동기화 검토 | 복수 기기 접근과 백업 요구 조사, 필요할 때 서버 저장 설계 | 실제 사용자가 기기 간 이동을 요구하고, 개인정보 처리·운영 책임을 정했을 때 시작 | 요구 검증 전 DB 구축 |
| 4. 협업·조직 기능 검토 | 공유·팀 템플릿·관리 기능의 필요성 조사 | 개인용 흐름이 작동하고, 조직 사용자의 별도 문제가 확인됐을 때 시작 | 개인 기록의 기본 공개 |

단계 2 이후의 기능은 **후속 후보**다. 위 표는 수요나 효과가 확인됐다는 근거가 아니다.

## 단계 1 통합·검증 순서

1. 홈의 선택적 상황 입력과 두 필수값만으로 저장되는 현재 구현을 고정 빌드에서 다시 검증한다.
2. AI 동의·호출·초안 검토의 화면과 서버 계약을 [API·AI 계약](API_AI_CONTRACT.md)과 대조한다.
3. 분석 결과·할 일 상세에서 팝업을 열고 항목 선택·적용 표시·새로고침 후 업무별 재조회까지 검증한다.
4. API 키가 있는 실제 환경에서 샘플 두 유형을 확인한다. 실패하면 원인을 기록하고 수동 흐름을 유지한다.
5. 변경된 실제 흐름에 맞춰 `README.md`와 시연 절차를 갱신한다.

## 다음 단계로 갈지 결정하는 기준

| 질문 | 수집할 관찰 | 판단 |
| --- | --- | --- |
| 사용자는 두 필수 칸만으로 구체적인 행동을 작성할 수 있는가? | 저장 완료율과 막힌 위치, 작성된 체크리스트의 구체성 | 어렵다면 문구·예시·선택 질문을 보완 |
| 저장한 항목을 다음 업무에서 다시 찾는가? | 무안내 재조회 성공과 필요한 시간 | 찾지 못하면 탐색·업무 분류를 먼저 개선 |
| AI 초안이 실제 작성 시간을 줄이고 사실 오류를 늘리지 않는가? | AI 사용·미사용 작업 시간, 수정량, 사실 오류 사례 | 효과가 불분명하면 AI 확장보다 수동 흐름 개선 |
| 기기 간 접근이 꼭 필요한가? | 실제 반복 사용자 인터뷰 | 요구가 확인되기 전에는 계정·DB를 만들지 않음 |

검증 방법과 기록 형식은 [검증 계획](VALIDATION_QA.md)에 둔다. 출시 단계의 변경 이유는 [결정 기록](DECISIONS.md)에 남긴다.
