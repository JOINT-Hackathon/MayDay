# 메이데이 디자인 시스템 · Mayday Dark

> 갱신: 2026-11-14 · Figma 디자인 페이지에 맞춰 Dark 테마 적용 · 화면 검증 범위는 FIGMA_IMPLEMENTATION.md 참고

## 1. 디자인 의도

**키워드:** 깊은 초록, 맑은 유리, 차분한 광택, 선명한 행동.

사용자가 첫 화면에서 **“경험을 다음 업무의 체크리스트로 바꾼다”**는 목적을 이해하도록 한다. 글래스 표현은 브랜드 분위기와 화면의 깊이를 만드는 데 쓰고, 긴 문장 입력·기록 조회는 읽기 쉬운 단색 표면에 둔다. AI는 시각적으로 주인공이 아니라 정리 시간을 줄이는 보조 기능이다.

`리퀴드 글래스`는 이 문서에서 **부드러운 빛 반사, 반투명 표면, 얕은 층 차이, 자연스러운 움직임**을 뜻한다. 내용이 뒤틀리거나 계속 움직이는 효과는 요구하지 않는다.

## 2. 색상 기준

Figma의 메인 그린 `#9CE266`, Noto Sans KR, 어두운 글래스 표면을 기준으로 합니다. 기존 변수명과 저장 흐름은 유지하며 `src/mayday.css`에서 화면 배치를 적용합니다.

| 역할 | 적용 값 |
| --- | --- |
| 기본 배경 | `#0A0F0D` |
| 배경 그라데이션 | `#10201B → #0A1513 → #030607`, 좌측 하단 청록빛 |
| 주요 글자 | `#F1F2ED` |
| 보조 글자 | `#D1D7CF`, 도움말 `#A7B1A8` |
| 주요 버튼 | `#9CE266`, hover `#B6ED89` |
| 버튼 글자 | `#162511` |
| 감정 카드 | 코랄 `rgb(229 134 128 / .18)` |
| 할 일 카드 | 그린 `rgb(156 226 102 / .13)` |
| 글꼴 | Noto Sans KR, 로컬 시스템 글꼴 fallback |
| 기본 제목 | 홈 36px, 결과 24px, 트랙 22px |
| 디자인 간격 | 4·8·12·16·20·24·32·40·48·64px |
| 주요 라운드 | 카드 10~24px, 버튼·칩 999px |

실제 합성 배경 위의 전체 대비 감사는 별도입니다. 오류·선택 상태는 색뿐 아니라 문장, 체크, `aria-*` 속성으로 구분합니다.

## 3. 글래스 표면 사용 규칙

| 영역 | 표현 | 이유 |
| --- | --- | --- |
| 홈의 핵심 소개와 제품 흐름 카드 | 깊은 녹색 배경 위 어두운 반투명 카드, 얕은 테두리와 그림자 | 첫인상과 서비스 목적을 함께 보여줌 |
| 상단 내비게이션 | 가독성을 유지하는 어두운 유리 표면, 스크롤 시에만 약한 블러 | 이동 위치는 명확하게 유지 |
| 저장 완료·핵심 체크리스트 | 은은한 글래스 외곽 또는 하이라이트 한 층 | 결과물이 시연에서 먼저 보이도록 강조 |
| 입력 폼·긴 기록·오류 메시지 | 불투명하거나 거의 불투명한 배경 | 글자 가독성과 입력 집중 유지 |
| 작은 버튼·칩 | 초록색 채움 또는 단색 테두리 | 터치·선택 상태를 빠르게 구분 |

한 화면에 강한 블러 표면은 **1~2개 주요 영역**에 집중한다. 유리 위에 유리를 여러 겹 쌓지 않는다. 배경의 장식이 본문이나 입력칸 아래에서 글자 대비를 흔들면 장식을 줄인다.

### 구현용 표면 예시

```css
.glass-surface {
  background: rgb(255 255 255 / 0.78);
  border: 1px solid rgb(255 255 255 / 0.72);
  box-shadow: 0 18px 48px rgb(16 42 34 / 0.10);
  -webkit-backdrop-filter: blur(16px) saturate(125%);
  backdrop-filter: blur(16px) saturate(125%);
}

@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .glass-surface { background: #FFFFFF; border-color: #D7E5DA; }
}

@media (prefers-reduced-transparency: reduce) {
  .glass-surface { background: #FFFFFF; -webkit-backdrop-filter: none; backdrop-filter: none; }
}
```

이 코드는 적용 위치를 정하기 위한 **예시**다. 실제 클래스 이름은 기존 구조에 맞추고, 투명도는 배경과 텍스트 대비를 보며 조정한다. `backdrop-filter`가 없어도 핵심 내용과 동작이 같아야 한다.

## 4. 타이포그래피·형태·움직임

- Noto Sans KR을 우선하며 `src/tokens.css`의 공간 토큰을 활용한다. 새 글꼴 다운로드가 시연의 필수 조건이 되지 않게 한다.
- 제목은 짧고 단단하게, 설명은 한 문장씩 쓴다. AI 관련 긴 주의문보다 **사용자 행동과 결과**가 먼저 보이게 한다.
- 카드 모서리는 기존 `--radius-card`를 기준으로 하고, 핵심 카드만 더 둥글게 확장한다. 모든 컴포넌트를 같은 강도의 둥근 유리 카드로 만들지 않는다.
- hover는 150–250ms의 작은 밝기·그림자 변화 정도로 제한한다. 버튼 클릭·저장·오류에는 분명한 상태 변화를 제공한다.
- `prefers-reduced-motion: reduce`에서는 장식 움직임을 멈춘다. 움직임 없이도 화면 순서와 상태가 이해되어야 한다.

## 5. 화면별 우선순위

1. **홈:** 초록색 분위기와 함께 “경험 → 체크리스트 → 다음 업무”가 5초 안에 읽힌다. 중앙 입력과 ‘메이데이 보내기’ 버튼을 주요 행동으로 둔다.
2. **경험 정리:** 사실과 체크리스트 입력을 우선 보여준다. AI 버튼과 전송 동의는 보조 영역에 두고 사용자가 작성한 내용이 가장 선명하게 보인다.
3. **저장 결과:** 감정·할 일 결과를 구분하고, 할 일 상세에서 체크리스트 팝업으로 이동한다.
4. **업무 시작·내 기록:** 기록 카드의 내용과 분류가 장식보다 우선이다. 빈 상태·오류는 유리 효과보다 안내 문장이 먼저다.

## 6. 접근성·성능 승인 기준

- 375px, 768px, 1024px, 1440px 폭에서 가로 스크롤 없이 주요 흐름을 완료한다.
- 일반 본문 글자 대비는 최소 4.5:1, 큰 글자는 최소 3:1을 목표로 한다. 반투명 배경 위 글자는 **가장 밝거나 어두운 실제 배경**에서 확인한다.
- 버튼·입력의 키보드 초점 윤곽을 지우지 않는다. 터치 대상은 최소 44×44px을 유지한다.
- 투명도 감소·모션 감소 설정에서 불투명 대체 표면과 정지된 화면을 확인한다.
- 구형 브라우저나 성능이 낮은 기기에서 블러가 없어도 사용 가능해야 한다. 큰 영역에 다수의 `backdrop-filter`를 중첩하지 않는다.
- 오류·선택·진행 상태는 색만으로 구분하지 않는다.

## 7. 구현 파일과 작업 순서

| 순서 | 파일 | 작업 |
| --- | --- | --- |
| 1 | `src/tokens.css` | 기존 변수 이름을 유지하며 목표 팔레트·그림자·표면 토큰 적용 |
| 2 | `src/base.css`, `src/styles.css` | 배경과 글래스 표면을 홈·내비게이션·결과에 제한적으로 적용. 폼·기록은 가독성 우선 |
| 3 | `index.html` | 기존 메타 색·파비콘 등이 파란색을 암시하는지 확인하고 필요한 경우에만 갱신 |
| 4 | 실제 화면 | 반응형·키보드·대비·블러 미지원·모션 감소 상태 점검 |

화면 담당 챗 하나가 위 스타일 파일을 소유한다. 다른 챗이 같은 파일을 수정 중이면 먼저 병합 순서를 정한다. 디자인 적용은 [MVP 기능 요구사항](REQUIREMENTS.md)의 저장·AI·재사용 흐름을 바꾸지 않는다.
